# 10x Genomics HDF5

Cell Ranger's `filtered_feature_bc_matrix.h5` and `raw_feature_bc_matrix.h5`,
and the same layout from Space Ranger, Xenium and CellBender. The file is
recognised by its content, whatever its name. Given alone, a Space Ranger or
Xenium matrix converts without its positions: convert the
[Space Ranger folder](visium.md) or the [Xenium bundle](xenium.md) to keep
them.

```bash
adata convert filtered_feature_bc_matrix.h5 -o counts.h5ad
adata convert raw_feature_bc_matrix.h5 -o rna.h5ad --feature-type "Gene Expression"
adata convert multiome.h5 -o sample.h5ad --split-feature-types
adata convert cellranger2.h5 -o mouse.h5ad --genome mm10
adata convert counts.h5ad -o out.h5 --layer counts
```

| Flag | Meaning |
|---|---|
| `--genome` | Keep this genome's features; picks the group in a Cell Ranger 2 file holding several |
| `--var-names` | `gene_ids` (default) or `gene_symbols`, scanpy's default |
| `--make-unique` | Suffix repeated var names as `var_names_make_unique` does |
| `--feature-type` | Keep one feature type, e.g. `"Gene Expression"` |
| `--split-feature-types` | Write one output per type, `OUT.<type>.h5ad` |
| `--layer` | Export: the matrix to write, `X` (default), `raw/X` or a layer |
| `--gene-ids-column` | Export: var column with gene ids (default `gene_ids`, else the var names when the names have a column) |
| `--gene-names-column` | Export: var column with gene names (default `gene_symbols`, else the var names) |
| `--feature-types-column` | Export: var column with feature types (default `feature_types`) |

Features are named by gene id, with the symbols in `var["gene_symbols"]`:
the layout `scanpy.read_10x_mtx(var_names="gene_ids")` gives. Ids are unique
where symbols repeat (Cell Ranger's GRCh38-2020-A reference repeats 10
symbols), with one exception: in a probe-level (Flex) matrix several probes
share a gene id. Repeated names are kept and reported, as scanpy does;
`--make-unique` suffixes them as `var_names_make_unique` does, and the ids
it suffixes are kept in `var["gene_ids"]` (symbols it suffixes are exported
suffixed). `var["probe_ids"]` names a Flex
matrix's probes.

With `--var-names gene_symbols`, reading gives the var names and columns
`scanpy.read_10x_h5(gex_only=False)` gives, checked against scanpy in CI:
`gene_ids`, `feature_types`, every other per-feature field Cell Ranger
recorded (`genome`, `pattern`, `read` and so on for antibody and CRISPR
features, `filtered_probes` for Flex), `probe_ids` for a Flex matrix, and
`filtered_barcodes` in obs where present. The default names by gene id,
which scanpy's `read_10x_h5` cannot. Other differences from scanpy:

* every feature type is kept unless `--feature-type` says otherwise;
* `X` keeps Cell Ranger's integer counts, where scanpy converts them to
  float32; run `adata recast out.h5ad X --inplace --dtype float32` if a tool
  needs floats. float16 values are read as float32, since scipy has no
  float16 sparse matrix;
* text outside ASCII, which Cell Ranger writes as XML character references
  (`&#947;`), is read as the characters they stand for, where scanpy shows
  the references;
* the run's metadata, which scanpy drops, goes in `uns["cellranger"]`.

The file is checked before anything is written: every array under
`features/` must have one entry per feature, every tag `_all_tag_keys` lists
must be there, `filtered_barcodes` must have one entry per barcode, and
`indptr` must run from 0 to the number of entries without going back. An
entry whose feature index lies outside the features is refused as the
matrix is copied, and the output is not kept. `--genome` with
`--feature-type` is refused when that genome has no feature of the type.

The matrix is stored genes x cells in CSC, which is byte for byte cells x
genes in CSR, so `data`, `indices` and `indptr` stream straight across;
`--split-feature-types` reads them once for every output.

Writing produces the Cell Ranger 3+ layout for CellBender, SoupX,
DropletUtils, Seurat and anything else that reads Cell Ranger output: gzip
compression and fixed-width ASCII strings, as Cell Ranger writes them, since
PyTables (which CellBender reads with) cannot read the variable-length kind.
Text outside ASCII is written as XML character references, as Cell Ranger
writes it, so that scanpy, which decodes these strings as ASCII, can read
it; a warning says how many names were written so, since scanpy shows the
references. A CSC or dense matrix is transposed or sparsified on the way, streaming.

Each feature needs an id, a name and a type. The name comes from
`var["gene_symbols"]` and the id from `var["gene_ids"]`, and the var names
stand in for whichever has no column: so a store named by id, as `convert`
writes one by default, exports with its symbols. The flags above name other
columns. If var has no ids and no `feature_types` column, the export is
refused, and `--force` writes the names as ids and `Gene Expression` as the
type. A matrix with `var["probe_ids"]` is written as Cell Ranger writes a
probe-level (Flex) matrix: the probe ids as `features/id` and the gene ids
as `features/gene_id`, with Cell Ranger's `gene_name`, `probe_region` and
`filtered_probes` where var has them, even if no import recorded them. A
missing value in a boolean field is written as False, with a warning, since
a 10x file cannot say a value is missing. A matrix of floats is written as it is, with a
warning, except float16, which is widened to float32 (with a warning too):
scipy has no float16 sparse matrix, so nothing could read it back. A file imported by `convert`
exports with its run metadata, its per-feature fields (booleans such as
`filtered_probes` stay boolean) and `filtered_barcodes` intact.
